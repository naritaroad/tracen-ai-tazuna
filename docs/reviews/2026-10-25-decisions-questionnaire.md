## Q02｜PostgreSQL 已定，選用的 SQLite 快取怎麼分工？

已確認正式系統以 PostgreSQL 為主。Android SQLite 快取是另一層，只服務離線閱讀與草稿，不取代後端的資料與工具。

- [ ] A【建議】正式系統只用 PostgreSQL。若之後確有離線需求，再在 Android 端加 SQLite 快取，不把產品主庫改成 SQLite。
- [ ] B：另外做一份伺服器端 SQLite，與 PostgreSQL 並存；產品仍以 PostgreSQL 為主，不做雙寫。
- [ ] C：維持單一 PostgreSQL，不做 SQLite。

建議原因：保留產品方向；不為了多一種資料庫而增加同步工程。

補充：＿＿＿＿。
